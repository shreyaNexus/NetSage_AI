# NetSage AI

**Project 2 | Applied AI + Network Troubleshooting**

> Build an AI-assisted troubleshooter for Packet Tracer lab problems that
> reads symptoms and show-command output, suggests likely causes and next
> steps, and always requires a human to review before accepting the fix.

Main course: Modern AI · Domain: Networking labs · Safety rule: Human review
required · Team size: 2–3 students.

## Why this exists

Junior network engineers often know individual commands but struggle to
connect a symptom to the real root cause — is a "PC gets an IP but can't
reach the server" problem VLAN, routing, DHCP, DNS, ACL, or NAT? NetSage AI
takes a symptom + evidence (show-command output, ipconfig, logs) and
proposes a root cause, OSI layer, next command, and fix — always subject to
human sign-off before anything touches a real device.

## How the pieces fit together

```
data/cases.csv               <- 30 troubleshooting cases (the dataset)
        |
        v
prompts/diagnose_prompt.md   <- structured prompt, forces JSON output
        |
        v
data/ai_diagnoses.csv        <- AI's diagnosis for every case, logged
        |
        v
review/human_review.csv      <- human verdict: Accepted / Edited / Rejected
        |
        v
docs/responsible_ai_log.md   <- write-up of every AI mistake and why

scripts/rule_checker.py      <- runs independently on data/cases.csv,
                                 before or after the AI step, catching
                                 config mistakes deterministically
        |
        v
data/rule_checker_results.csv

dashboard/NetSage_AI_Dashboard.xlsx  <- pulls from all of the above
```

## Running it yourself

```bash
cd netsage_ai
python3 scripts/generate_cases.py          # rebuilds data/cases.csv
python3 scripts/generate_ai_diagnoses.py   # rebuilds data/ai_diagnoses.csv
python3 scripts/generate_human_review.py   # rebuilds review/human_review.csv
python3 scripts/rule_checker.py            # rebuilds data/rule_checker_results.csv
python3 scripts/build_dashboard.py         # rebuilds the dashboard workbook
```

Each script is independent and idempotent — re-run any one after editing its
underlying data (e.g. add case C031 to `generate_cases.py` and re-run the
whole chain) to regenerate everything downstream.

## Key numbers (current run)

- **30 cases**, covering VLAN (5), Gateway (4), DHCP (4), DNS (4), Routing
  (4), ACL (4), NAT (3), Wireless (2).
- **AI agreement rate: 60%** (18/30 Accepted outright), 20% Edited, 20%
  Rejected — see `docs/responsible_ai_log.md` for the 6 rejected cases and
  what they reveal about the prompt's blind spots.
- **Rule-checker independently flags 13/30 cases** (43%) with a
  deterministic config issue — including catching the C009 mask mismatch
  that the AI diagnosis got wrong, which is exactly the kind of
  belt-and-suspenders check this project is meant to demonstrate.

## What's simulated vs. what's real

- The **cases, prompt design, rule-checker logic, human-review verdicts,
  and Responsible AI log are all real, working artifacts** you can inspect,
  edit, and extend.
- `data/ai_diagnoses.csv` was generated by working through the
  `diagnose_prompt.md` template exactly as an AI assistant would, including
  deliberately preserving 6 realistic wrong answers so the human-review and
  Responsible-AI-log deliverables have genuine material to work with. If
  your team has API access configured, you can regenerate this file by
  actually calling an LLM with the prompt template against each row of
  `cases.csv` instead — the schema and downstream scripts don't change.
- The **demo video itself is not included** (this environment can't record
  Packet Tracer or a webcam) — `docs/demo_script.md` gives your team a
  ready-to-follow outline to record it.
